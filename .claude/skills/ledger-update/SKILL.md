# 台帳に値を足す・直す

体の値と設備の高さは、すべて `data/values_ledger.json` から読む（CLAUDE.md）。コードに数字を書かない。

## 手順

1. **原典を開く。** 検索結果の抜粋や要約で済ませない。PDF なら表番号とページまで確かめる（例：こども家庭庁 2024 表2 p.2）。
   - 二次引用（別の報告書が引いている値）しか見られないときは、その経路を `source` に書く（例：`ZUKAN2013（TOKYO_KYOGIKAI2018 で引用）`）。
2. **出典を `_meta.sources` に登録する。** キー（例 `CSIC2025`）、著者・年・題名・発行元・URL。値の `source` はこのキーを含める。
3. **区分を付ける。** `_meta.categories` の4つだけ：
   - `measured` 根拠あり（実測）／`formula` 根拠あり（推定式）／`converted` 要換算（出典の値に式を当てた）／`provisional` 仮値。
   - 二次引用（`secondary_citation: true`）、出典に「未確認」とある値、式の有効範囲の外への延長は、根拠あり（measured・formula）にしない。
   - **格上げしない。** 迷ったら弱い方の区分にする。区分を上げたいときは KO に理由と原典の場所を見せて決めてもらう。
4. **食い違いは KO に決めてもらう。** 原典どうしが違う値を出しているときは、候補・違い・それぞれの理由を並べて見せる。決まったら `_meta.decisions` と項目の `note` に「【決定 日付】採用した値と理由」を残す。
5. **確かめる。**
   - `npm run check:ledger`（出典の書き忘れ・格上げ・コードに係数を書いていないか）
   - `npm test`（台帳の値を読むテストを足す。例：15か月の登れる高さ 39.9cm）
6. **記録する。** dev-log-entry の手順で docs/dev-log.md に1節。プロジェクト資料「値の台帳」も更新する（原典で確かめる箇所・仮値のまま残る項目の表）。

## してはいけないこと

- 記憶やもっともらしさで数字を埋める。
- 仮値を「根拠あり」と書く、二次引用を実測と書く。
- 台帳の式の係数（1.59・0.9842 など）を sim/・render/ に数字で書く（hooks が止める）。
